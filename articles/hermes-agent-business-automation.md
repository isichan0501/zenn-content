AIに文章を作らせるだけでは、業務はなかなか自動化できません。

調査結果をファイルに保存したり、定刻に処理を実行したり、失敗したら原因を調べたりするには、LLMと外部ツールをつなぐ「エージェント」が必要です。Hermes Agentは、会話を起点にファイル操作、Web調査、コマンド実行、スケジュール処理などを組み合わせられるオープンソースのAIエージェントです。

この記事では、Hermes Agentを使って日常業務を自動化するまでの考え方と実装手順を、定期レポート作成を例に解説します。

:::message
この記事のゴールは、単発の「AIへの質問」を、繰り返し実行できる「業務フロー」に変えることです。
:::

## Hermes Agentとは

Hermes Agentは、Nous Researchが公開しているAIエージェントです。ターミナル、デスクトップアプリ、Webダッシュボード、メッセージングサービスなど、複数の画面から同じエージェントを利用できます。

一般的なチャットAIとの違いは、回答を生成するだけでなく、許可されたツールを使って実際に作業できる点です。

- Webやドキュメントを調査する
- ファイルを読み書きする
- シェルコマンドやスクリプトを実行する
- 複数のサブエージェントへ処理を分担する
- 過去の設定や好みをメモリとして保持する
- 定期処理をcronジョブとして実行する
- 結果をチャットや各種メッセージングサービスへ届ける

モデルやプロバイダーを固定せず、用途に応じて選択できるのも特徴です。利用可能な機能や対応サービスは更新されるため、導入時には[公式ドキュメント](https://hermes-agent.nousresearch.com/docs/)も確認してください。

## 自動化に向く業務を見つける

最初から「会社の業務を全部自動化する」と考えると失敗しやすくなります。まずは、次の条件に当てはまる小さな業務を選びます。

1. 定期的に発生する
2. 入力元が決まっている
3. 完成形を文章で説明できる
4. 成否を確認できる
5. 間違えたときの影響が小さい

たとえば、次のような仕事です。

- 毎朝、指定した情報源を調べて要点をまとめる
- 会議メモから決定事項と担当者を抽出する
- 複数のCSVを集計して週次レポートを作る
- GitHubのIssueやPull Requestを確認して進捗を報告する
- 新しい補助金・助成金情報を収集し、条件に合うものだけ通知する

一方で、送金、契約締結、顧客への一斉送信、本番データの削除などは、最初から完全自動化すべきではありません。まず「下書きを作る」「候補を抽出する」までを自動化し、人間が確認してから実行する形にします。

## セットアップ

公式のインストーラーを利用する場合は、次のコマンドを実行します。

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

インストール後、セットアップウィザードで利用するモデルやプロバイダーを設定します。

```bash
hermes setup
hermes doctor
```

`hermes doctor` は、依存関係や設定に問題がないかを確認するコマンドです。モデルを変更したい場合は、次のコマンドから選択できます。

```bash
hermes model
```

普段の対話は `hermes` で開始できます。単発の指示だけを実行したい場合は、次のように指定します。

```bash
hermes chat -q "今日の作業メモを読み、未完了のタスクを整理して"
```

APIキーなどの秘密情報は、プロンプトや業務ファイルへ直接書かず、Hermesの認証・設定機能で管理します。

## 自動化を作る5つの要素

Hermes Agentの業務自動化は、次の5要素に分けて考えると設計しやすくなります。

### 1. 指示：何を完了とするか

「ニュースを調べて」のような曖昧な指示では、結果が安定しません。入力、対象、出力形式、失敗時の動作まで書きます。

```text
指定した3つの公式サイトから、過去24時間に公開されたAI関連情報を確認する。
重複を除き、重要度の高いものを最大5件選ぶ。
各項目にタイトル、要約、URL、公開日時を付ける。
一次情報を取得できなかった項目は掲載しない。
新着がなければ「本日の新着なし」と報告する。
```

大切なのは、エージェントが迷わないことよりも、結果を人間が検証できることです。

### 2. ツール：会話を実作業につなげる

調査ならWeb、集計ならコード実行、文書管理ならファイル操作というように、目的に合うツールを有効にします。

```bash
hermes tools list
hermes tools
```

`hermes tools` では、利用するツールセットを対話的に管理できます。必要以上に多くのツールを有効にせず、業務に必要な範囲へ絞ると、誤操作と複雑さを減らせます。

外部サービスを連携する場合は、既存のツールやMCPサーバーが利用できるかを確認します。

```bash
hermes mcp list
hermes mcp add <名前> --url <MCPサーバーのURL>
hermes mcp test <名前>
```

### 3. スキル：成功した手順を再利用する

毎回長い指示を書く代わりに、業務手順を「スキル」として保存できます。スキルには、使う場面、具体的な手順、注意点、完了条件を記述します。

```bash
hermes skills list
hermes skills search "report"
```

スキル化に向いているのは、何度も使う手順です。

- 週次レポートの作成ルール
- 自社向けの記事執筆ガイド
- 問い合わせメールの分類基準
- システム障害時の確認手順

うまくいかなかったときは、その場しのぎでプロンプトを追加するのではなく、原因と検証方法をスキルへ反映します。これにより、改善した手順を次回以降も再利用できます。

### 4. メモリ：安定して使う前提を残す

担当者名、好みの出力形式、プロジェクトの規約など、今後も変わりにくい情報はメモリに保存できます。

ただし、すべてを記憶させるのは逆効果です。日々変わる進捗、長いログ、秘密情報は、メモリではなく業務ファイルやデータベースで管理します。

目安は次の通りです。

| 情報 | 保存先 |
| --- | --- |
| 好み、役割、安定した規約 | メモリ |
| 再利用する作業手順 | スキル |
| 日々の進捗、処理履歴 | ファイルやデータベース |
| APIキー、トークン | 認証・秘密情報管理 |

### 5. スケジュール：定期実行する

動作が安定したら、cronジョブとして定期実行します。Hermesでは、自然言語に近い間隔指定やcron式を利用できます。

```bash
hermes cron create "0 9 * * 1-5" \
  "指定した公式サイトの新着情報を確認し、日本語で朝の業界レポートを作成して"
```

スキルを読み込ませる場合は、`--skill` を付けます。

```bash
hermes cron create "0 9 * * 1-5" \
  "新着情報を収集し、重複を除いて朝のレポートを作成して" \
  --skill daily-industry-report \
  --name "平日の業界レポート"
```

ジョブの一覧や状態は次のコマンドで確認できます。

```bash
hermes cron list
hermes cron status
```

定期ジョブは通常の会話とは別の新しいセッションで実行されます。そのため、「いつものサイトを見て」のような省略は避け、情報源、出力先、判定基準をジョブまたはスキルに明記します。

## 実践例：毎朝の業界レポートを作る

ここからは、毎朝の情報収集を自動化する流れを見ていきます。

### ステップ1：まず手動で実行する

最初はスケジュールせず、通常の会話で依頼します。

```text
以下の公式情報源を調査し、過去24時間の更新をまとめてください。

対象:
- サービスAの公式ブログ
- サービスBのリリースノート
- 官公庁Cの発表ページ

条件:
- 一次情報だけを使う
- 重複を除く
- 重要度順に最大5件
- 各項目に要約、公開日時、URLを付ける
- 取得できないサイトがあれば、推測せず失敗理由を書く
```

出力を読み、不要な記事が混じった理由や、必要な情報が抜けた理由を確認します。

### ステップ2：完了条件を追加する

次に、品質を判定するチェック項目を追加します。

- URLが一次情報を指している
- 公開日時が対象期間内である
- 同じ発表を重複掲載していない
- 要約だけで業務への影響が分かる
- 情報がない日は無理に記事を作らない

自動化では、「何をするか」と同じくらい「何をしてはいけないか」が重要です。

### ステップ3：スキルとして固定する

安定した手順をスキルへまとめます。スキルには情報源だけでなく、除外条件と検証方法も含めます。

```markdown
# Daily Industry Report

## 手順
1. 指定された公式サイトを確認する
2. 過去24時間の更新だけを抽出する
3. URLと公開日時を照合する
4. 重複を除いて重要度順に並べる
5. 日本語のMarkdownレポートとして保存する

## 失敗時
- 取得できない情報を推測で補わない
- 取得失敗した情報源と理由を報告する
```

### ステップ4：定期ジョブへ移す

数回の手動実行で品質を確認してから、平日の朝に実行するジョブを作ります。

```bash
hermes cron create "0 9 * * 1-5" \
  "daily-industry-reportスキルに従ってレポートを作成して" \
  --skill daily-industry-report \
  --name "平日9時の業界レポート"
```

特定のプロジェクト内でファイルを読み書きするジョブでは、作業ディレクトリも明示します。

```bash
hermes cron create "0 9 * * 1-5" \
  "前回レポートとの差分を確認して今日のレポートを作成して" \
  --skill daily-industry-report \
  --workdir /path/to/report-project
```

## 複雑な業務はサブエージェントへ分ける

調査対象が多い場合、1つのエージェントへすべてを詰め込むより、役割を分けた方が管理しやすくなります。

たとえば、次のように分担できます。

- 調査担当：複数の情報源から候補を集める
- 検証担当：日付、URL、重複、一次情報かどうかを確認する
- 編集担当：読者向けに要約し、体裁を整える

Hermes Agentには、サブタスクを別コンテキストで動かすための委任機能があります。ただし、担当を増やすほど常に品質が上がるわけではありません。1つの作業で十分な場合は分割せず、コンテキストが大きすぎる、独立した調査を並行したい、といった場合に利用します。

## 安全に運用するためのルール

### 書き込み処理は段階的に自動化する

最初は次の順番で権限を広げます。

1. 情報を読むだけ
2. 下書きを作る
3. 人間の承認後に送信・公開する
4. 条件を限定して自動実行する

メール送信や記事公開を自動化するときは、宛先、公開先、件数上限、重複防止条件を設定します。

### 成功だけでなく失敗を通知する

「処理が終わった」だけでは不十分です。最低限、次の内容を残します。

- 実行日時
- 参照した情報源
- 作成・変更したファイル
- 成功した処理
- 失敗した処理と理由
- 人間による確認が必要な項目

取得結果が空だったのか、通信に失敗したのかも区別します。

### 秘密情報をプロンプトに入れない

APIキーやアクセストークンを、スキル、cronプロンプト、Gitリポジトリへ書かないようにします。認証情報はHermesの認証機能や環境設定で管理し、エージェントの出力にも表示させません。

### 定期的に見直す

外部サイトの構造、API、社内ルールは変わります。自動化が動き続けていても、正しい結果を出しているとは限りません。

- 情報源が現在も有効か
- 出力に抜けや重複がないか
- スキルの手順が古くなっていないか
- 利用モデルやAPIの費用が想定内か
- 不要な権限を持っていないか

これらを定期的に確認します。

## まとめ

Hermes Agentで業務を自動化するときは、いきなり完全自動化を目指す必要はありません。

1. 小さく、検証しやすい業務を選ぶ
2. 手動実行で指示と完了条件を固める
3. ツールを必要な範囲だけ有効にする
4. 成功した手順をスキルにする
5. 安定してからcronで定期実行する
6. 書き込みや公開には人間の確認を残す

AIエージェントの価値は、何でも自律的に実行することではなく、繰り返し作業を「確認可能な手順」に変えられる点にあります。まずは、毎週作っているレポートや、毎朝確認している情報源を1つ選び、下書き作成までの自動化から始めてみてください。
